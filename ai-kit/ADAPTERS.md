# اتصال به ابزارهای کدنویسی
تاریخ بررسی مستندات: 2026-10-26. رفتار دقیق به نسخه و تنظیمات ابزار بستگی دارد. قابلیت خواندن Markdown مشترک است؛ کشف خودکار یکسان نیست.

## روش همگانی و مطمئن‌تر
پوشه کامل `ai-kit` را مثلاً در ریشه پروژه کپی کن. در چت بنویس:
«فایل ai-kit/START_HERE.md را بخوان، سپس CORE و memory/STATE و فقط راهنمای مرتبط را بخوان. ریشه پروژه همین workspace است. خواسته من: ...»
اگر ابزار فقط چت است، فایل‌ها را پیوست یا متن آن‌ها را منتقل کن. گفتن مسیر کامپیوتر به چت ابری به‌تنهایی دسترسی نمی‌دهد.

## Codex و ابزارهای پشتیبان AGENTS.md
در AGENTS.md ریشه پروژه یک بخش کوتاه اضافه کن: «برای کارهای این پروژه ai-kit/START_HERE.md و ai-kit/CORE.md و ai-kit/memory/STATE.md را بخوان؛ راهنماهای دیگر فقط به تناسب کار.» فایل موجود را جایگزین نکن. قرار گرفتن AGENTS.md فقط داخل ai-kit الزاماً کدهای خارج از آن را پوشش نمی‌دهد. دستورهای نزدیک‌تر و تنظیمات میزبان را بررسی کن.

## Claude Code
یک بخش در CLAUDE.md ریشه با همین مسیرها اضافه کن یا از روش import مستند در نسخه خود استفاده کن. این بسته برای سازگاری، ارجاع صریح به خواندن فایل را پیشنهاد می‌کند؛ پشتیبانی AGENTS.md و بارگذاری را در تنظیمات همان نسخه کنترل کن. فایل موجود را حفظ کن.

## Cursor
AGENTS.md ریشه یا یک قانون `.cursor/rules/ai-kit.mdc` با توضیح کوتاه و `alwaysApply: true` می‌تواند مسیر ورودی را معرفی کند. فایل md معمولی در rules را معادل rule فعال فرض نکن. ابتدا قوانین موجود را ببین.

## GitHub Copilot
در `.github/copilot-instructions.md` بخش کوتاه ارجاع را اضافه کن. پشتیبانی دستورها در GitHub، IDE و code review متفاوت است؛ بررسی کن قابلیت مورد استفاده آن فایل را می‌خواند. ارجاع مسیر تضمین نمی‌کند همه فایل‌ها خودکار وارد context شوند؛ برای کار حساس مسیر را در درخواست هم ذکر کن.

## ابزار دیگر، از جمله Antigravity و Windsurf
بدون اثبات مستندات نسخه، نام فایل یا دستور اختصاصی را حدس نزن. از معرفی صریح START_HERE در چت یا بخش project instructions ابزار استفاده کن. برای هر ابزار تازه: محل rules، scope، اولویت، بارگذاری و محدودیت اندازه را از مرجع رسمی بررسی کن.

## نصب بدون خراب‌کردن پروژه
1. اگر ai-kit از قبل هست، ابتدا مقایسه و پشتیبان؛ فایل حافظه پروژه قبلی را روی پروژه جدید کپی نکن.
2. در پروژه جدید از حافظه خالی همین بسته شروع کن. مسیر دلخواه مانند docs/ai-kit مجاز است؛ همه ارجاع‌ها و تنظیم HTML را مطابق آن تغییر بده.
3. HTML حافظه و کد پروژه را نمی‌خواند؛ فقط فرم و فایل‌های انتخابی خودت را پردازش می‌کند.
4. حالت کامل HTML برای چتی است که فایل محلی ندارد؛ حالت ارجاع برای عامل دارای دسترسی پروژه است.
5. تغییر Markdown بعد از ساخت HTML نیاز به انتخاب دوباره پوشه در HTML دارد؛ نسخه تعبیه‌شده خودکار از دیسک تازه نمی‌شود.
